The user guide pages (`getting-started.md`, `installation.md`, `local-mode.md`, `mcp.md`, `configuration.md`) are product facing. Write them for the person using or operating Whisperer, in the house writing style: sentence one carries the point, no em dashes, semicolons, colons or parenthetical asides in prose, and a screenshot from `assets/screenshots` before the detail. Implementation rationale, test evidence and incident history go in the developer reference pages or the nearest README, never in the user guide.

Configuration requirements belong in `configuration.md` and nowhere else. Never put secret values in examples.
